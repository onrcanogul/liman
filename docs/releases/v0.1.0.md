The first release of liman, a small PaaS for a single server. It is a
**pre-release**: everything below runs in CI on fresh Ubuntu machines,
but liman has not yet run on a real server, behind a real domain.

## What it does

`limand` runs on the server, `liman` on your machine. A deploy pulls an
image, starts the container with limits, checks its health, points the
proxy at it and retires the previous release, with a rollback at every
step.

- **Zero-downtime deploys and rollback**, with the steps shown as they run
  (`--dry-run` shows the commands you would type by hand).
- **Engines:** Docker, or rootful Podman.
- **Proxies:** Nginx, Caddy or Traefik, or none: workers, and apps on a
  fixed port.
- **Deploys from CI:** a trigger endpoint with a key per app, the image
  checked in the registry by digest, and previews of a pull request with a
  key that cannot deploy.
- **Secrets** encrypted at rest, write-only over the API, as environment
  variables or files; master key rotation.
- **Health monitoring** with restarts, an audit trail anchored in the
  system log, daily backups, and a web panel at `/ui/` (rollback, secrets,
  tokens, backups; deploys stay with the command line).

## Installing

Download the binary for your server and `SHA256SUMS`, then check both
that the files are intact and that this repository's release workflow
built them:

```
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify limand-linux-amd64 --repo onrcanogul/liman
chmod +x limand-linux-amd64
sudo ./limand-linux-amd64 install
```

`limand install` looks at the server, asks which engine and proxy to use
(or takes `--engine`, `--proxy`, `--listen`), and sets up the user, the
systemd units and the proxy's side. The README's "Installing on a server"
has the rest, from the private network to the first token.

## Known limits

- Not yet tried on a real server; certificates from Let's Encrypt are
  tested only against Pebble, its test CA.
- Linux only. The arm64 binaries are built but not run in CI.
- Podman only as root (rootless is not supported yet).
- The API has no TLS of its own: it listens only on private addresses
  (WireGuard, for one).
- Configuration and API may still change before 1.0.
