The third release of liman, a small PaaS for a single server. It is
still a **pre-release**: everything below runs in CI on fresh Ubuntu
machines. What it adds came from moving the first real app, a Spring
Boot API with its database on the server, onto liman.

## What is new

- **Apps reach the server as `host.docker.internal`** on Docker, rootful
  Podman and rootless Podman alike, with nothing in `app.yaml`: a
  database installed on the server is
  `jdbc:postgresql://host.docker.internal:5432/app`. Docker on Linux did
  not know the name; liman now adds it. The README's "A database on the
  server" has PostgreSQL's side (`listen_addresses`, `pg_hba.conf`, the
  boot order), and CI deploys an app that writes to it.
- **`healthcheck.timeout`**: how long a release may take to become
  healthy, 1s to 10m; 30s without it. A JVM app that starts in half a
  minute was undone before. It is kept on the container, so a rollback
  waits as long, and the health monitor gives an app it restarted at
  least that long before checking it again.
- **Logs stop growing.** On Docker's default `json-file` driver liman
  caps each container's output at 20 MB in five files; on rootless
  Podman's `k8s-file`, 20 MB. Other drivers keep their own settings.

## Upgrading

```
sudo ./limand-linux-amd64 install
```

Running containers keep what they were started with: the
`host.docker.internal` name and the log cap arrive with each app's next
deploy. A pipeline that uses `healthcheck.timeout` needs this release's
`liman` too, since `liman trigger` checks the definition before sending
it.

## Installing

The server:

```
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify limand-linux-amd64 --repo onrcanogul/liman
chmod +x limand-linux-amd64
sudo ./limand-linux-amd64 install
```

The CLI on a Mac:

```
gh release download v0.1.2 --repo onrcanogul/liman -p liman-darwin-arm64 -p SHA256SUMS
shasum -a 256 --check --ignore-missing SHA256SUMS
gh attestation verify liman-darwin-arm64 --repo onrcanogul/liman
chmod +x liman-darwin-arm64 && sudo mv liman-darwin-arm64 /usr/local/bin/liman
```

The macOS binaries are not notarized by Apple; one downloaded with a
browser has to be cleared first with
`xattr -d com.apple.quarantine liman-darwin-arm64`.

## Known limits

- Not yet tried on a real server; certificates from Let's Encrypt are
  tested only against Pebble, its test CA.
- Rootful Podman does not tell liman its log driver, so liman leaves its
  logs alone; with `k8s-file`, set `log_size_max` in `containers.conf`.
- The arm64 Linux binaries and the macOS CLI are built and checked for
  their platform, but not run in CI.
- The API has no TLS of its own: it listens only on private addresses.
- Configuration and API may still change before 1.0.
