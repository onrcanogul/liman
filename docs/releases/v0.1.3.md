The fourth release of liman, a small PaaS for a single server, and the
first that is not marked a pre-release: from now on only tags with a
hyphen (`v0.2.0-rc1`) are. liman is still early, and configuration and
API may change before 1.0.

## What is new

- **A one-line install.** `get.sh` comes with every release: it picks
  `limand` for the server's architecture, checks it against `SHA256SUMS`
  (and the build attestation when `gh` is logged in), installs nothing
  if either fails, then runs `limand install` with the flags given:

  ```
  curl -fsSL https://github.com/onrcanogul/liman/releases/latest/download/get.sh | sudo sh -s -- --listen 10.8.0.1:7070
  ```

  To read it first: download it with `curl -fsSLO`, read it, run it with
  `sudo sh get.sh`. CI runs it end to end, piped to `sh`, on a fresh
  Ubuntu machine.

## Upgrading

```
curl -fsSL https://github.com/onrcanogul/liman/releases/latest/download/get.sh | sudo sh
```

An upgrade asks nothing and keeps `config.yaml`; running apps are not
touched. The CLI on a Mac:

```
gh release download v0.1.3 --repo onrcanogul/liman -p liman-darwin-arm64 -p SHA256SUMS
shasum -a 256 --check --ignore-missing SHA256SUMS
chmod +x liman-darwin-arm64 && sudo mv liman-darwin-arm64 /usr/local/bin/liman
```

## Known limits

- The management API listens only on private addresses: from your
  machine, over WireGuard or an SSH tunnel.
- A proxy that runs in a container is not driven by liman; publish the
  app on a fixed address and point the proxy at it.
- The arm64 Linux binaries and the macOS CLI are built and checked for
  their platform, but not run in CI.
