# A health check timeout of the app's own, and capped logs: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An app sets how long it may take to become healthy, kept for
rollbacks; containers' logs stop growing where the driver is `json-file`.

**Architecture:** A new `healthcheck.timeout` flows from `app.App` into
the deployer's state and onto a container label; `waitHealthy` uses it.
The docker client learns the log driver at `Connect` and adds rotation
options in `Start`.

**Tech Stack:** Go 1.27, the moby client, gopkg.in/yaml.v3.

**Spec:** `docs/superpowers/specs/2026-11-22-jvm-ready-design.md`

## Global Constraints

- Default timeout 30s; allowed 1s to 10m.
- Definitions without the field keep their checksum.
- Log options exactly `max-size=20m`, `max-file=5` for `json-file`.
- Repo text is English; commits end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `go test ./...` and `make lint` pass after every task.

## Review Focus

- A rollback to a release deployed with a long timeout: must use it, not
  30s (label round trip, tested in Task 1).
- A label written by hand with a huge or malformed timeout: `trusted`
  ignores it, the default applies.
- An image `HEALTHCHECK` whose window is longer than the app's timeout:
  the longer one still wins.
- A daemon whose default driver is journald: no options are sent (an
  option the driver does not know fails the container's creation).
- Rootless Podman with `k8s-file`: the cap must not break `liman logs`.
